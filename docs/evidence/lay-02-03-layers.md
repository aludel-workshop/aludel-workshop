# LAY-02 and LAY-03: the layers are real

Authorization: owner, 2026-09-22, after reviewing prototype v2: "this looks awesome. go ahead and make it real. make sure that you're documenting this all". Scope and packets are in the [implementation plan](../design/portal-layers/implementation-plan.md). These results are agent-checked; the owner has not yet walked through the real layers.

## What exists

| Area | Result |
|---|---|
| Project shell (LAY-02) | `/p/<slug>/<layer>/<tab>/<id>` for members. Rail: Home, Product, Design, Pages, Platform, Work; Settings; account menu (account, your apps, sign out). Global search across stories, specs, docs, research, pages and work. Non-members see "Project not found" and get 404 from the API. "Continue in Aludel" and "Your apps" open here; Aludel's own hash workspace is unchanged (LAY-06) |
| Knowledge store (LAY-03) | `server/knowledge.mjs`: `knowledge_records` with a per-kind validator (vision_section, persona, phase, activity, step, story, spec, research, doc, page), `knowledge_revisions` with author and rationale, and `layer_work_items`. Story status is derived: defined (acceptance) → designed (a designed page or done design work) → built (done implement work); it is never set by hand |
| Story packs | `config/story-packs.json` (8 packs). Packs seed ordinary activities, steps and stories, and place their pages, merging into an existing page with the same name. Unselecting removes only untouched pack content. Only Accounts sign up, sign in and sign out are marked template-built, because only those are really generated by aludel-web-v1 |
| Onboarding writes into the layers | Claim seeds phases and the vision statement. The feel seeds pages (until the navigation is customised). Functionality (before Pages) applies packs. The Pages editor saves page records and asks which page takes a deleted page's stories. A build records one done "Aludel template" work item, and the template stories become Built |
| Layers UI | **Home:** phase progress by derived status, needs you, app, recent decisions. **Product:** Vision sections with rationale, personas, story map (add activities, steps and stories; drawer editing Given/When/Then, edge cases and clarifications), roadmap phases, specs (Shape Up plus requirements), research, docs with templates. **Design:** foundations with DTCG-shaped tokens derived exactly as the scaffold derives them, components, patterns, guidelines, sources and deviations. **Pages:** tree, a live canvas using the shared `page-blocks`, description, type and notes, story links, mark designed, flows per activity. **Platform:** architecture (stack, entities from specs), repository, environments with rebuild, connections (the shared agent component). **Work:** queue by state; suggestions computed from gaps (missing acceptance, open clarifications, undesigned pages) with Start now and Add to queue; item page with question and answer, compiled context citing sources, "will document", assignment, state moves (closing requires named outputs); working style and preference switching |

## Known gaps (not claimed)

- **Answers and closures are not yet verified against records.** Answering a question stores the answer on the work item, and closing requires named outputs, but nothing checks that the named story or page actually got a new revision linked to the item. The next step (LAY-04) is to link revisions to `work_item_id` and verify on close.
- **Agents do not act yet.** Assigning "Agent" is a label; working-style automation and routines are described but not running (LAY-04).
- Design-system tabs are read-only apart from the Look & feel editor. Components and guidelines are not yet editable records.
- The navigation is edited in the onboarding Pages editor (`/start/<id>/pages`, linked from the Pages layer), not inline in the layer.
- Onboarding still writes a PW-02 `direction` product record alongside the vision statement. Retire it when Aludel moves into layers (LAY-06).
- The interim `/projects/<id>` page still exists. Nothing links to it any more; remove it in LAY-04.
- No Storybook stories for the layer components.

## Retrospective

1. **What made it harder?** Global CSS class collisions again (the account and section patterns). Zoneless rendering meant tests filled forms from the previous tab. Accessible names disappeared when narrow CSS hid text. A select sized by its longest option overflowed at 390px. Page status updates written as "decisions" flooded the history.
2. **What would make the next equivalent task easier?**
   - The `lay-` prefix for every layer class (applied).
   - Tests wait for the destination's own content before filling (applied throughout `layers-browser.mjs`).
   - Status changes write no rationale; only decisions do (applied in `recordBuild`).
   - Every form control gets `max-width: 100%` (applied).
3. **Effect on the plan:** LAY-04 now has a concrete first job: verify outputs through revision links and write answers into target records. Agents come after that, not before.
4. **Questions:** Should closing "define" work require the story's acceptance to have changed in the same item? Recommended: yes. Should Aludel's own records move in LAY-06 before or after agents? That one is the owner's call.
5. **Process change and test:** the handoff plan's "Current state" was updated mid-work, before an interruption, and the session resumed from it. That shows it works as a handoff within one session; a fresh-session handoff is not yet tested.
