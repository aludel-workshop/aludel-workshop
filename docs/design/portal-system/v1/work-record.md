# Foundation reset and recursive project coverage

## Outcome, authority and process

Owner direction: treat existing pages as wireframes, reconsider view interactions from intent through the design-system philosophy, and map what capabilities/tools cover across the product vision. Further clarification: Aludel is a project within itself; the primary distinction is shared global structure versus project-specific realization. DEC-021/022 record these directions. Authorized work includes reversible foundation records and bounded design exploration; no production transition, spending or external deployment is implied.

Process weakness: preserving an old usable flow as a UI baseline can freeze its arbitrary grouping; classifying tools only as inside/outside the portal obscures recursion. Improvement: separate enduring product semantics from reopenable compositions; use one capability contract with explicit project allocations and service relationships, including self-development.

Success: every explored composition traces to a view intent and system principle; both Aludel and BorrowBox fit the same coverage schema without implicit tool inheritance; unproven integration and authority overlap remain visible. This is groundwork inside D-01F, not an extra parallel packet.
