## Content and interaction contract

- **Visible:** project/layer context, title, description, assignee, priority and Queue/Backlog. Defaults are shown; creating saves work without starting an agent.
- **Criteria:** optional list, not a multiline “one per line” field. Add creates one editable plain criterion with removal; never silently add a generic criterion. Label these as reviewer judgment rather than automatic proof.
- **Journeys:** optional in-form picker, searchable by journey and showing revision and steps. The owner selects whole journeys or specific steps; the task references stable IDs/revisions, not rewritten text. Specify is an optional action in the picker; attaching no journey is valid. Route matching is guidance at agent assessment. Multiple references deduplicate by journey ID/revision; no-journey and no-search-result states remain distinct.
- **Unknown route / no attached journey:** Create saves directly. At pickup the agent assesses affected journeys and augments owner selections; several journeys may cover different personas. If a relevant journey is missing, propose Specify. If none applies, use suitable non-journey review evidence. Neither infer triviality nor force a journey from an absent route match.
- **Context:** creation opens as a focused modal above the board. Minimize preserves the draft and returns to the board; reopening restores it. Explicit close prompts before discarding a dirty draft. No nested dialogs: journey picker expands within the composer.
- **Keyboard:** labelled controls, visible focus, dialog focus containment, Escape collapses a picker before closing the composer, focus restores to the triggering control. Ctrl/Cmd+Enter uses the same create path, including an explicitly selected Specify task. Enter in the description adds a newline.
- **Failure:** failed save preserves all content and permits retry. Validation names the affected field. Changing a stale journey revision requires reconfirmation in implementation; the prototype does not fabricate backend conflict handling.
- **Responsive:** narrow composer fills the screen, metadata wraps, picker replaces supporting content within the same scroll area, footer remains reachable. No squeezed three-column form.
- **State:** title-only, long description, zero/one/multiple criteria, zero/one/many journeys, no search result, dirty close, dock/resume, failed save, Specify prerequisite and successful creation.

Existing Aludel MD3 profile and portal tokens remain the design foundation. The modal/title-description/chip-footer composition is borrowed from Jira Quick Create; the optional criteria/journey section is Aludel-specific. The experimental readiness interruption was removed following owner feedback.
