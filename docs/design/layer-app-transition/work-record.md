The transition needs two independently addressable builds with separate writable state and a shared scenario ledger before behavior is compared. The existing portal has typed `knowledge_records`, `layer_work_items`, `routine` records and `routine_runs`; the prototype has none of its authentication, persistence, Work review or recovery guarantees. The process improvement is to require an isolation proof and baseline parity before layer runtime changes, and to forbid a production cutover from being inferred from candidate UI approval.

**Readiness for planning:** ready. Current portal records and code paths are available, and the owner specified the comparison boundary. **Readiness for implementation:** the first isolated scaffold packet is ready to select later; the broader kernel and cutover packets depend on observed isolation and contract evidence. Project-wide `next_action` remains `WORK-AGENTS-01` until the owner explicitly reprioritizes it.
