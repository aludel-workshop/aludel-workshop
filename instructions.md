# Aludel
Hi. I need a product which i can use to build products. I need to be able to go from rough client spec to demo in a day, build the mvp in week and get testers into it, and by the end of a month have something gorgeous, scalable, and maintainable. I want to manage this process using a single portal, which can integrate with everything i need - git, deployment, coding agents. I want to deal in the realm of product vision - how should it feel, what problems does it solve? I want to wave a hand and say i need a feature that does x - the product helps clarify the intent with precise language, decision points, mockups. it handles the in between of structure - pages, databases, apis. breaks down implementation plan, assigns tasks, returns to me the interactive and documented build to review before pushing. More than just following my prompts, i need it to continuously self improve, discovering work items (bugs, CI, refactors, etc), prioritizing, implementing them. We don't have to assume user is tech-illiterate: everything should be observable/accessible to humans as much as agents. Things like workflow, process  design, etc, can be important human expert input points. 

i called this the machine that builds itself, because its first and constant project is itself. To start this out, you're just running on my local machine. but the goal asap is to get this live and capable of creating equivalent live projects. So that i can transition to doing this work within the app - whatever the rollout plan is, is visible from within the app, managed and built by agents spun up in environments on the app server. an interesting recursion: the portal can be used to develop projects, and the first project is the portal itself.

Nothing is out of scope. deployment, marketing and outreach, analytics, design. my main direction for you is to start small, and plan for the future: as ai agents develop, we don't want to be stuck in an overly restrictive framework. this needs to be modular, adaptable. I would advise doing a good bit of research first, and documenting findings within the app in a way that they can continue to inform future decisions (and remember, this is the research strategy for the apps this app is deploying as well! What is our mvp to get this created? How does it evolve long term, with eyes open to all the knowledge types that will be collected and made accessible? That structure of feature product mapping, mvp, long term vision; how is that handled in the app in turn?). You can have for this bootstrap the github, jira, codex, digital ocean credentials (my default stack, but please, don't consider those imperative - use whatever frameworks and tools you think are most appropriate: i don't want this at all constrained by what i ame most comfortable with, i want it the result of your research into best implementation - and of course flexible in that we want to be able to easily swap out agent providers, servers, whatever without blinking) you need to get running, but when we transition to developing further in the app, what does the process of interfacing with those other tools look like? And again to clarify this recursive feeling design: not all apps created by this product will need github within the app itself. but the portal itself which is used to create these other apps, each project in it will probably need its own version control integrated for developing that app. and don't over-rely on outside apps, like getting figma prototypes - very likely agents can do better mockups with image gen and just creating a web page mockup from the internal design system representation (how are these mockups stored/version controlled/used in eval? is there a point where that is no longer necessary?)

don't feel like you have to just guess at what i want. ask me questions, plenty of them (what does the feature look like for a project surfacing questions/decisions to the owner? Your initial task is just research and definition. don't need to solve it all in a single session, just lay the groundwork for the continuous improvement.
